05

Delegating an outcome delegates its ordinary means

Routine, proportionate delivery actions inside the named scope are already authorized.

1
Isolate and inspect

Create the established worktree and inspect the scoped repository state.

2
Edit and verify

Make scoped changes and run the relevant tests, lint, builds, and behavioral checks.

3
Commit and publish the task branch

Commit intentionally, push the declared branch, and create or update its pull request.

4
Repair causal blockers

Own CI, review, or integration failures that causally prevent the delegated outcome without expanding into adjacent scope.

5
Land and prove the outcome

Follow the repository-declared merge, deployment, and verification path. These ordinary means do not need the product decision to be reconfirmed.

07

Capability truth outranks symmetry

One client's hook model is not evidence for another client.

  • Merge authorization — resolves repository authorization; it does not itself observe green status.
  • confirm_class — reserved configuration; not currently enforced by the merge gate.
  • Deployment metadata — informational to the outcome resolver; it does not execute or authorize a deployment command.
  • Codex continuation — supported startup and tool-use events are fixture-backed, but there is no Stop/final-response hook. Final-response discipline is guidance-only.
  • Claude Code continuation — uses its own supported lifecycle hooks; support remains version- and fixture-specific.
08

A question is action-local

  • One action needs a consequential decision — preserve the question and block only that action and its dependents.
  • Other work is independent and authorized — continue it immediately; do not ask whether to keep working.
  • A side question arrives — answer it, then resume the delegated workflow unless the user explicitly redirects it.
  • No authorized route remains — report input_required with the single narrow decision that unlocks progress.

This is the normative doctrine. Native prompt suppression and action-local scheduling remain adapter capabilities that must be implemented and proven separately.

09

A gate must earn the attention it consumes

REPAIR

Can the agent recover?

A denial must name the failed invariant and the authorized route to repair it.

TRANSPARENCY

Why does it exist?

The local failure and its place in the delivery system must both be visible.

FLEXIBILITY

Can valid work pass?

Exceptions require reasons and evidence; a gate must not make safe work impossible.

LEARNING

Will the rule improve?

Replayable evidence must support tuning or removing machinery that no longer helps.

Add a gate only for a repeated or high-severity failure with an independent oracle that rejects bad cases and permits good ones.

10

How the current adapters cooperate

The implementation is concrete; the capability boundaries remain replaceable.

DESIGN
Adversarial discovery writes an OpenSpec change. Intent, non-goals, risks, requirements, controls, and the walking skeleton become reviewable artifacts.
BREAK DOWN
Beads stores the executable dependency graph. Ready work can be allocated without turning task state into policy authority.
EXECUTE
Client agents work in isolated Git worktrees. Independent lanes proceed from explicit ownership and a reviewed outcome oracle.
VERIFY + LAND
Independent checks prove the user-visible result; repository policy owns landing. GitHub is today's delivery adapter. Passing unit tests alone is not proof when the outcome lives elsewhere.
11

Boundaries matter

Ordinary means are bounded. A causal blocker inside the delegated repository, audience, privilege, and effect boundary is owned. An adjacent opportunity is tracked without silently expanding scope.
A prompt can still appear. Until a host adapter can express existing semantic authority, its sandbox may still request mechanical approval. That is an enforcement gap, not a new intent decision.
Unsupported means unsupported. Stored configuration, another client's hook, or prose intent does not prove green-status checks, confirmation enforcement, deployment execution, or final-response interception.
Personal state is not bundled. Authentication, permissions, project memory, and task databases remain user- or repository-owned.

The mission outlives the tools

Today's adapters and intellectual roots make the mechanism concrete.

  • Mission command and Grove's leverage — purpose, decision rights, and capacity directed toward outcomes
  • Closed-loop control — compare observed behavior with an independent target and repair divergence
  • Lean flow and constraint management — measure delay and protect the delivery path
  • Enabling bureaucracy — gates provide repair, transparency, flexibility, and learning
  • Walking-skeleton and test-oracle practice — probe the riskiest assumption and verify the result independently
  • OpenSpec, Beads, Git, and GitHub — valuable current adapters, not permanent product identity
